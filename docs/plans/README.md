# Plans

This directory is the record of what was planned, what was built and where the building departed
from the plan. Each plan says its status in its first lines and is updated as it is built; the
code is the last word, and the architecture page is drawn from it.

A design made in Claude Docs (or any other artifact) is a working draft for talking a plan
through. Once a plan here exists, the plan wins where the two differ, and the draft is not kept
up to date.

## For agents

The person's policy, `.pigeon/policy.toml`, says what agents acting for them may do. Call `policy_check` (Pigeon MCP) before acting (a push, a landing, messaging or starting a session, a change to the gate) and again after any refusal. Act on `allow` as the person's standing instruction. On `deny`, stop and tell the person the rule and its reason. Never propose new rules or loosen one: only the person changes the policy, and a change to it lands only with their passkey. Tests live in the smoke suite alone: `tests/smoke.rs` and its area modules in `tests/smoke/`; `.claude/settings.json` is generated from the policy, never edited by hand.

**Where work runs** (`docs/plans/ai-agents.md`):
- **By default, work runs inside pigeon**, through its model gateway: `ai_agents_start {role, brief}`.
  - Use a `planner` for a piece of work: it plans, spawns executors, reviews their branches and
    lands phase by phase.
  - Use an `executor` for one well-specified change: it pushes its branch and runs CI, and never
    lands.
- **When the person asks for the Claude chat** ("do it in the Claude chat", "in a Claude Code
  session", "in chat"), start a Claude Code session instead with `create_session`. Then:
  - record it with `ai_agents_register`;
  - ask it to call `ai_agents_report` with its run's id as it goes and at its end.
- **When the person asks for Codex in ChatGPT**, start a native Codex subagent in the
  ChatGPT conversation. Register it with `ai_agents_register {runtime: "codex_chat",
  session_id, role, brief}` using the agent's session identifier. Record progress and the
  final result with `ai_agents_report`. The parent can report for the child when the child
  lacks the Pigeon connector. Use the authorized source checkout for repository work.
  Pigeon tracks the run while ChatGPT runs the agent.
- **Read `ai_agents_inbox`** whenever the person writes, and after starting a run. Relay a run's
  questions and reports. Answer a question with `ai_agents_answer`.
- **Stop** one run with `ai_agents_stop`, or every run with `ai_agents_pause`.

The first change taken into main by `land` (rather than merged by hand) was a one-line docs commit on `claude/land-check-2`.
