# Cost and instance settings

This iteration follows [the app plan](ios-app-sessions.md), [gateway accounting](model-providers-cloudflare.md), [instance pins](versioning.md) and [the release process](ios.md). Each numbered phase is reviewed and lands on its own; the app ships only after the server and detail screens land.

1. Extend `models_daily` and the closed-day cost rollups without changing the meaning of existing fields. Group actual model names by the configured gateway, including active gateways without spend; do not infer the gateway from a model name. Do not invent attribution for old totals. Keep using the existing gross total (Anthropic reconciliation and estimated Unified Billing fee included). A public config lists promotional grants, their expiries and dated applications. The grant balance is lifetime; only applications in the requested period reduce that period's gross. No purchased balance is a discount. No credentials, private identifiers or illustrative grants in the live config.
2. Cost uses one series per gateway/model or Cloudflare product for both the always-open billing cells and daily chart. Show dollars, gross vs net, the period dates, and individual promo balances and expiry warnings on the Anthropic BYOK cell. Keep source failures distinct from no spend. Use the brief's dark palette for these views, without editing generated design tokens.
3. Put pushed titles beside Back. Use device-local readable timestamps. Group secrets by service with missing slots first; use only the authorised secret-entry path. Retry a cancelled Users load once, preserving the last good list and its timestamp.
4. Keep Settings intact. Add missing-secret and upgrade counts, and an enabled-capabilities screen grouped by upgrade impact. Use the real instance plan and record, never demo versions. An upgrade is a proposed pin edit awaiting the owner's existing passkey flow; only a confirmed record change counts as applied. Show migration instructions rather than claiming arbitrary manual migration steps ran automatically.
5. Small usability improvements: persist the cost period, inspect a day, refresh detail screens and surface urgent expiry / breaking updates in Needs you. Avoid adding expensive polling.

## Phase 1 API and storage decisions

- Share the platform's gateway declarations between the model gateway and cost assembly. Keep the retired gateway only in periods with known historical spend; an active gateway appears even at zero spend or when logs are unavailable. Gateway `provider` describes the configured payer (`anthropic`, `openai`, `cloudflare`, or `other` for the retired gateway). Model `provider` is the log's underlying provider slug, and model `name` is the logged ID, not a family or a shortened Workers AI ID.
- `models_daily.by_gateway` contains log cost per gateway/day and per provider/model/day. It is additive; the existing family, provider, route and reconciliation fields are unchanged. `cost_daily.ai_gateway.by_gateway` is raw log spend, not a share of reconciled gross. A gateway not yet provisioned contributes no logs to `models_daily`; other read errors still fail the source. An old rollup without gateway detail is not attributed. Merge new detail per gateway, retaining an existing snapshot when that gateway's new listing is truncated or absent.
- A public, checked-in promo-only config records grant names, USD cents, expiry dates and dated USD-cent applications. It starts empty. Balances are lifetime through today; after expiry the spendable remaining balance is zero (expiry is not spend). The eligible grants are subscription-included API credits, never purchased top-ups at any provider. An empty ledger means not configured. `net_total` is gross minus applications on dates in the response's `days`, with no inferred or purchased-credit discount and no zero floor.

Declare the additive `models` and `observability` answers as 1.1.0, still compatible with 1.0.0 callers.

## Phase 2 design

- Replace the square cards with one net-cost hero, one daily stack chart and always-open billing cells. Put the range control beside Cost and show the dates returned by `cost_daily` in the hero. All keeps daily bars and scrolls when they don't fit. Pull-to-refresh remains; day selection and range persistence wait for phase 5.
- Use the server's gross and net as-is. The difference is promotional credits applied in the period, not the lifetime grant balance. Use `cloudflare.lines` and `ai_gateway.by_gateway[].by_model` for both the chart and the rows. The chart shows reported daily detail, which need not add up to gross when older spend has no attribution or gross includes billing adjustments. Do not spread period totals across days or guess missing gateway detail. Keep source failures, missing detail and no spend distinct.
- Give each series its own colour within its billing family (BYOK orange, Unified Billing yellow/green, Cloudflare products blue). Keep the supplied palette local to Cost. Show gateway labels and model names, not gateway IDs. Put lifetime grant balances in the Anthropic BYOK cell, sorted by expiry, then name. Use UTC calendar days for expiry warnings and distinguish an empty grant list from a missing one.
