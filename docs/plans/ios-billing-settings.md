# Cost and instance settings

This iteration follows [the app plan](ios-app-sessions.md), [gateway accounting](model-providers-cloudflare.md), [instance pins](versioning.md) and [the release process](ios.md). Each numbered phase is reviewed and lands on its own; the app ships only after the server and detail screens land.

1. Extend `models_daily` and the closed-day cost rollups without changing the meaning of existing fields. Group actual model names by the configured gateway, including active gateways without spend; do not infer the gateway from a model name. Do not invent attribution for old totals. Keep using the existing gross total (Anthropic reconciliation and estimated Unified Billing fee included). A public config lists promotional grants, their expiries and dated applications. The grant balance is lifetime; only applications in the requested period reduce that period's gross. No purchased balance is a discount. No credentials, private identifiers or illustrative grants in the live config.
2. Cost uses one series per gateway/model or Cloudflare product for both the always-open billing cells and daily chart. Show dollars, gross vs net, the period dates, and individual promo balances and expiry warnings on the Anthropic BYOK cell. Keep source failures distinct from no spend. Use the brief's dark palette for these views, without editing generated design tokens.
3. Put pushed titles beside Back. Use device-local readable timestamps. Group secrets by service with missing slots first; use only the authorised secret-entry path. Retry a cancelled Users load once, preserving the last good list and its timestamp.
4. Keep Settings intact. Add missing-secret and upgrade counts, and an enabled-capabilities screen grouped by upgrade impact. Use the real instance plan and record, never demo versions. An upgrade is a proposed pin edit awaiting the owner's existing passkey flow; only a confirmed record change counts as applied. Show migration instructions rather than claiming arbitrary manual migration steps ran automatically.
5. Small usability improvements: persist the cost period, inspect a day, refresh detail screens and surface urgent expiry / breaking updates in Needs you. Avoid adding expensive polling.

Release via `ios-release` at main HEAD; the release service assigns the next build number and submits to TestFlight. Do not submit to App Review or alter approval policy.
